# 滚动时分隔线闪烁（v0.1.42）

用户提供的 3.40 秒、59.97 fps 录屏共 204 帧，已全部解码并逐帧查看。滚动时可见分隔线交替消失：第 3 帧某条分隔线局部亮度约 188，而周围背景约 232；相邻应有分隔线的位置只有约 230 的背景。多个移动帧仅检出约 8 条清晰分隔线，静止阶段约 16 条。变化发生在视口中部，排除了正常的顶部/底部渐隐区域。

原列表使用 0.5 DIP 高度的 Border。125% 缩放时只有 0.625 个物理像素，小数滚动偏移改变边缘采样与舍入，使线条变淡或消失。新的 PixelAlignedDivider 保留原来的布局尺寸、背景画刷、边距与各行坐标，仅将绘制高度限制到至少一个完整物理像素，并使用 GuidelineSet 对齐上下边缘。窗口切换 DPI 时重绘；没有对文字、图标、开关、页面布局或整个滚动视口强制像素舍入。

修复统一覆盖托盘列表、七行系统列表、设置列表及各页加载占位。弹层分隔线不在本次替换范围内。

回归从当前托盘 XAML 读取实际分隔线，在含边缘渐隐遮罩的视口中模拟 24 个小数滚动偏移。100%、125%、150%、200% 的 DPI，浅色 alpha 176、深色 alpha 48 下，分隔线的纵向覆盖总量与峰值保持恒定，且 ActualHeight 仍为 0.5。旧控件在 100% 的峰值从 44 到 88 变化，能复现原问题。

API 依据：[WPF 像素对齐](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.visualtreehelper.getysnappingguidelines)、[SetRootDpi](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.visualtreehelper.setrootdpi)。

验证命令：构建并执行 tests/InputMethodUiTests，其中已有的图标、滑块、弹层间距、滚动条不改变布局以及页面占位回归一并执行。另以真实窗口滚动录屏复测，并比对系统/设置控件的窗口内坐标、尺寸和持久配置。

实机同样的上下滚动路径各录制 420 帧并逐帧量化：旧版清晰分隔线数最少 7 条、193 帧低于 12 条；新版始终为 15～17 条，低于 12 条为 0 帧，范围变化来自视口边缘进出。系统及设置控件在窗口内的坐标和尺寸与旧版一致，持久配置逐项保持，已修复的打包应用替换规则仍正常应用。
