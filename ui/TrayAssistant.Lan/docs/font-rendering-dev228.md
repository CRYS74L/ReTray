# dev.228 加粗文字的静止渲染

针对 dev.227 调整过的名称、详情标题和表单文字出现锯齿感的问题，保留字号、字重、字体与现有界面比例，改进文字的显示渲染和控件的动画收尾。

## 证据与改动

- 本机 `PingFang SC` 的 SemiBold 请求选中 Medium 字体文件，`Microsoft YaHei UI` 的 SemiBold 请求选中系统 Bold 文件；两者的 `GlyphTypeface.StyleSimulations` 都为 None。因此没有按“伪粗体”假设更换字体或回退字重。
- 窗口原先继承 `Ideal / Grayscale / Animated` 文字设置。调整过的名称、详情标题、输入框、密码框、下拉触发器和菜单文字现在使用 `Display / Auto / Fixed`，静止时按显示像素对齐。普通正文保留原有设置；透明卡片上的文字由 WPF 选择可支持的抗锯齿路径，只有有不透明底色的输入内容与下拉触发内容启用 ClearTypeHint。
- 原表单的 ScaleTransform 初始化以及每次状态更新都创建动画时钟，完成后默认 HoldEnd。旧版本的“静止下拉框不应残留缩放动画时钟”回归检查失败。
- 静止且目标未变化时不创建变换动画；真正的缩放与箭头旋转从当前呈现值继续，完成后释放时钟。使用每个变换属性独立的代次，避免快速反向时旧的完成事件取消新动画。
- 下拉弹层展开结束后，同步释放位移和透明度动画时钟，回到静止位置与不透明状态。关闭和中途反向仍遵循现有交互。

## 验证

- 同一字体、字重和内容生成 100% / 125% / 150% / 200% 的渲染选项对比图，图像与辅助脚本存入 `.tools/ui-dev228`。
- Release 构建零警告、零错误。
- `--apple-controls-regression` 完整通过，包括静止下拉框、松开后的输入框、展开完成后的弹层均不残留变换时钟，以及原有按压收缩、菜单反向开合、图标字体、侧栏布局和浅深色检查。
- 已安装至 `C:\Path\To\LanDeviceMonitor`，663 个发布文件 SHA-256 一致；检查了实际窗口截图，主窗口响应正常，12 台在线和 7 台离线设备、实时流量与上下线历史继续正常显示。旧安装文件已备份在 `.tools/deployment-backups`。

主观的锯齿观感不能由属性断言代替，最终仍以本机安装版本在实际显示缩放下的显示效果为准。
