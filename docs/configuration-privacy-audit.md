# 历史源码与发行包中的配置核查

本次在 v0.1.43 之后、v0.1.44 提交之前执行，只读检查未修改 Git 历史。

## 覆盖范围

- 已同步远端全部分支和标签：v0.1.0 至 v0.1.43，共 44 个可达提交。
- 额外检查本地 reflog 中曾撤回的图标试稿提交；该提交仍能通过 GitHub 提交 API 读取。
  合计 45 个历史提交、1123 个独立文件对象：1021 个文本、84 个二进制，以及 18 个字体对象。
- 检查全历史文件名、可解析配置对象、与当前个人规则关联的路径及悬停文本签名；
  将 13 份托管图标与历史二进制做 SHA-256 对照。字体不作个人配置文本扫描。
- 检查本地现存的 v0.1.41、v0.1.42 MSIX，以及 v0.1.43 MSIX 和免安装 ZIP 的全部条目。
- GitHub 当前没有 Releases 附件，也没有 Actions artifacts；标签的源码下载对应上述 Git 树。

## 结果

未发现个人 `settings.json`、备份、`activity.json`、窗口位置文件或 `.trayconfig` 导出包
进入这些源码历史或发行包；未发现包含个人规则的可解析配置对象。

文本签名命中均为通用应用名 Codex 出现在测试和技术文档中，不是导入了个人悬停配置。
图标散列命中仅有旧版本自带的 `Assets/AppIcon.ico`，它也出现在个人托管图标目录中；
这是软件原有默认资源，与个人规则文件被打包是两回事。v0.1.43 的包没有该资源匹配。

历史技术文档确实保留了本机联调时的应用名、软件版本、部分路径、系统组件身份和环境说明。
因此结论是“没有发现上述个人配置文件或配置导出包”，不是“历史中完全没有本机环境信息”。
未来上传前仍需检查暂存区；`artifacts`、`dist`、`publish`、本地配置及证书不进入源码提交。
具体扫描结果与可能涉及本机路径的材料仅保存在被忽略的 `artifacts/privacy-audit`。
