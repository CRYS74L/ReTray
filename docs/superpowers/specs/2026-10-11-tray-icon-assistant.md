# 托盘图标助手：独立软件设计方案

日期：2026-10-11。状态：用户已确认计划，产品实施中。功能状态以实际测试和运行证据为准。

## 1. 要达到的结果

开发独立的 Windows 托盘管理软件，覆盖本地 PS Tray Factory 3.2 所体现的用户功能。独立程序负责识别、显示、隐藏、替换、排序和恢复图标，不要求安装或运行 PS Tray Factory 或 Lyrics Tray Icon Fix。界面默认中文，采用现代 Windows 桌面交互。当前采用低饱和度云母 ALT；顶栏下方直接显示页面内容，不重复选项卡标题；连接中显示占位行，正常运行不占用状态块。

用户明确提出的三项故障必须进入验收：其他软件新增图标后，自定义图标仍有效；登录后直接应用隐藏和替换规则，无需重启 Explorer；关机、注销过程中及时退出，不阻止系统结束会话，不重新拉起后台进程。自身托盘图标的显示开关和自定义图标也是必备功能。

补充的强制要求：完整识别当前 Windows 的真实托盘对象，包括 PS Tray Factory 漏掉的现代软件；不得让原本没有显示的旧 Windows 10 系统图标出现；微信自定义图标后，来消息的闪烁和原来的右键菜单仍有效。Lyrics Tray Icon Fix 的形成原因是上述漏识别及异常系统图标问题，新产品必须从底层处理，不能再次依赖该补丁。

本设计不把“界面做好”“构建通过”“某个 API 返回成功”视为完成。完整功能和受影响行为均通过实际验证后，才能称为符合上述要求。操作系统适配遇到困难时继续修复；某个必备功能若仍不工作，交付状态保持未完成。

## 3. 方案比较与选择

| 路线 | 优点 | 代价及结论 |
| --- | --- | --- |
| **WinUI 3 界面 + 轻量原生后台 + 独立托盘适配层（推荐）** | UI 可按需退出；规则、系统适配和产品交互各自独立；仅需对 Shell 进行必要控制 | 原生托盘的完整枚举、替换和排序包含 Windows 内部接口适配，需要先验证当前版本；这项难点作为首个必过关口 |
| 对每个软件安装通知 API Hook | 可以在应用创建或更新图标时改写参数 | 需要覆盖多个位数、权限和进程生命周期；侵入范围较大，不能保证处理已经存在的图标；不作为默认路线 |
| 替代整个任务栏或桌面 Shell | 自有托盘可以完全控制布局 | 改变日常桌面体验，兼容责任显著扩大；不选作本产品路线 |

推荐路线保留 Windows 自身任务栏和原软件的交互。隐藏图标可以由助手的快捷面板访问，但这不能替代“原生托盘里的图标替换、隐藏、排序”验收。

明确选择：**保留原始托盘注册身份，在原生显示层定制外观，在原生模型取得实时目录。** 不将第三方图标删除后注册为助手代理，不把固定替代图标覆盖到每一个源帧，不恢复缓存里的外部图标。微信菜单继续由微信的原始回调处理，闪烁继续由源动态更新驱动。

独立软件仍可能需要一个很小的 Explorer 内组件。独立指的是不依附原产品或旧补丁，并不等于 Windows 官方已经提供全部第三方图标控制 API。托盘内部协议需要按系统版本适配，产品必须区分可用功能与未通过验证的功能。

> 2026-10-11 当前产品范围以用户最新指示为准：竖向小窗口、顶部选项卡、全部图标列表、每行外置显示/隐藏开关、图标直接执行原生左右键/双击。删除窗口收起、密码保护、产品内旧规则迁移及列表筛选；助手菜单只保留打开助手与退出。取消全局恢复与暂停逻辑，软件运行时应用配置，退出时清理自身修改并保留配置。此前文档中的相关要求已撤销。个人现用规则在产品完成后通过本机独立步骤迁移，个人数据不进入源码或默认配置。

## 5. 组件、数据流和所有权

### 5.1 进程与模块

`TrayAssistant.exe`：WinUI 3 桌面界面，只在打开设置、列表或完整快捷面板时运行，负责交互和配置编辑。

`TrayAssistant.Agent.exe`：轻量 C++/Win32 后台，负责状态机、图标目录、规则、快捷键、自身托盘图标、原生快捷菜单、窗口恢复及会话退出。关闭界面不会结束规则；关闭后台是明确的“退出助手”动作。

`TrayAssistant.ShellBridge.dll`：当前会话 Explorer 的最小适配组件，取得已验证的通知模型事件、实现原生显示层定制和必要的窗口/菜单操作。源通知和身份默认原样保留。禁止使用全局线程 Hook 0；如果使用线程 Hook 安装组件，只定位真实托盘窗口所属线程，并在该线程内完成子类化。其他软件进程不作为默认注入目标。

`Core`：与 UI 和 Shell 分离的规则与生命周期逻辑；`Platform`：Windows 版本和通知协议适配；`Diagnostics`：可导出的状态、错误码、耗时及功能证据。

界面通过限制为当前用户和当前会话的命名管道与后台通讯。Shell 回调读取已经准备好的只读规则快照，执行有界本地判断，然后异步汇报事件。磁盘读取、图标解码、进程路径解析、UI 通讯和耗时规则编译都放到回调之外。

### 5.2 图标身份和增量处理

区分运行时实例与持久规则：运行时身份至少包含进程实例、HWND、UID 或 GUID；进程实例需要校验创建时间，防止 PID/窗口句柄复用。持久规则优先使用稳定 GUID，再结合应用身份或规范化路径及图标区分字段；可变提示文本和随机窗口类只能作为用户选择的附加条件。

每个图标同时保存 `OriginalState` 和 `EffectiveState`。原软件更新图标或提示时只更新原始状态；自定义规则从最新原始状态重新求出有效状态，动态帧优先按下文的兼容契约处理。NIM_MODIFY 不意味着撤销规则，NIM_DELETE 会取消这个运行时实例并释放对应资源。禁止把替换后的图标再次当作“原图”保存。

通知成员按对应 NIF 标志增量合并；未带标志的字段不能清空既有值。callback、GUID、通知版本、气泡通知及状态掩码分别处理。NIM_SETVERSION 的版本只在这个命令中解释，普通更新不能误读同一 union 为版本。源图标与助手自己的托盘图标使用不同命名空间。

新增、修改、删除事件按稳定身份合并到目录，界面增量更新。手动复核可以取得完整快照，但合并时保留规则、选择项、排序键、活动时间和图标资源所有权。序号只用于展示，不用于绑定规则。

窗口句柄、HICON、通知版本和跨位数载荷全部需要明确所有权及格式验证。来源图标在必要时复制，替代图标在创建方释放源句柄后仍有效；旧资源在没有回调引用时释放。反复替换不能泄漏 GDI/USER 句柄，也不能在 Explorer 仍使用它时销毁。

### 5.3 本机适配首关

在 Windows 26200 上先证明以下能力：取得已经存在的真实图标；识别 GUID/UID；取得原图及回调目标；完整隐藏；原生图标替换与提示替换；后续更新保持规则；可靠撤销；原生排序；正常卸载适配组件。

现有应用目录采用本机匹配的 `Taskbar.dll` 原生模型读取：校验 PE、PDB GUID/age、关键函数特征及集合稳定性后，从 NotificationAreaIconManager2 和 promoted/overflow 集合取得条目。已取得本机 11 条应用记录，包含微信及 GUID/非 GUID 同 HWND/UID 双记录；这部分不使用已失效的旧 COM 回调。源图像必须另行按真实类型验证，不能将 WinRT 图像对象地址误当 HICON。

Windows 11 内置托盘控件使用 `Taskbar.View.dll` / SystemTray 的 XAML、WinRT 对象路径单独适配，先分类再控制；不为它们注册替代 Win10 通知图标。未知系统版本先只读核对，适配缺口显示为明确状态；不能猜测偏移继续写入，也不能用遮住整个托盘替代单项功能。

采用分层适配，已有公开 API 优先。对必须使用的内部托盘接口与消息载荷，明确系统版本、结构大小、位数、协议字段及回退边界。当前只读 COM 结果和旧 toolbar 结果都不足以成为可用实现。必要时继续以本地逆向材料、Windows 符号和隔离实验寻找正确的当前版本接入点。

首次获取现有图标不能依赖手动重启 Explorer，也不能用 UIA 显示文字、注册表历史项或旧快照假装实时图标。避免向整个系统广播“任务栏已重建”来强迫所有软件重建图标。真正无法识别的通知消息原样交回 Windows；未知版本绝不猜偏移写入。

后端失联时 Shell 组件停止接管，及时把消息交回原处理链。正常停用时恢复当前有效图标的最新原始状态并安全移除组件；不能卸载仍被窗口过程引用的 DLL。界面崩溃不影响后台；后台崩溃时恢复 Windows 自然行为的路径需要独立验证。

## 6. 故障防护与行为兼容

### 6.1 图标刷新与自定义失效

规则属于持久身份，不属于列表位置或某次扫描结果。所有图标创建/修改入口都经过同一套规则，替换、隐藏和提示策略具有幂等性。重复事件不重复添加图标，处理自己的更新要带来源/序列标识防止递归。

快照复核只补差异；不会清空原始/有效双状态。新图标引起托盘重新布局时，已存在图标仍保留有效策略；如果 Shell 重新建立图标条目，新的生命周期也重新匹配持久规则。

### 6.2 登录启动与 Shell 重建

登录启动直接运行后台的 `--background`，通过当前用户自启机制配置，路径完整引用并可在界面查看真实状态。默认不使用 VBS 启动链或无限 Watchdog。

启动状态为 `Starting → WaitingForShell → LoadingExistingIcons → ApplyingRules → Ready`。后台先读取配置；Shell 尚未就绪时有界重试，并监听相关窗口/进程事件；就绪后取得现有图标并立即应用规则，同时接收新图标事件。首次应用与后续通知之间必须消除丢事件窗口。

监测 Explorer 进程实际退出和任务栏自然重建，进入 `Reconnecting` 并使用新一代目录/组件句柄；老进程句柄、过期图标或安装状态不能继续显示为 ready。状态页只有在枚举、规则应用和必要验证通过后才显示“运行正常”。

静止状态以事件等待为主。恢复窗口的重试有截止时间，间隔有退避；不把高频全列表扫描作为常态修补。

### 6.3 关机、注销与取消关机

后台必须创建顶层隐藏窗口接收会话消息；仅创建 message-only 窗口不足以替代这条广播接收路径。UI 和后台均在 `WM_QUERYENDSESSION` 中立即同意结束会话，不弹出确认、不等待磁盘、管道、Hook 或 UI 线程。

查询阶段禁止启动新的恢复进程，并等待系统是否真正结束会话。`WM_ENDSESSION(TRUE)` 进入 `SessionEnding`，停止重连、重试及拉起逻辑，有界释放资源并退出；`WM_ENDSESSION(FALSE)` 表示其他程序取消关机，恢复正常运行状态。不能在查询阶段就不可逆地删除配置、恢复所有窗口或禁用长期自启。

所有可接受的设置在正常编辑时持久化，关机不承担保存大型配置或图像的责任。后台使用显式状态机决定是否允许恢复，不能仅由一个文件标记或 Explorer PID 消失推断“应该重启”。退出后台、系统结束会话、意外故障是不同状态。

正常退出恢复助手自己最小化的窗口；会话真正结束时不重新显示大量窗口、不创建新的后台或 GUI 进程。中途取消关机后快捷键、规则和窗口恢复功能必须继续可用。

### 6.4 完整识别与旧系统图标

目录以已确认的实时原生对象及成功源注册为准，跨会话只保存偏好，不保存可被直接重放的第三方注册包。源 DELETE、对象销毁及 owner 退出移除运行时条目；Explorer 新一代会话重新取现存模型，不能把上一代缓存重新 NIM_ADD 到新托盘。

当前记录若只是 overflow、NIS_HIDDEN、透明闪烁帧或暂时没有响应，仍是有效图标，不能当成历史垃圾删除。不能只凭“同一个软件、同一 HWND、同一 UID”合并记录：本轮真实读取发现同 HWND/UID 的 GUID 项与非 GUID 项并存。

旧补丁里 explorer.exe/ATL:/UID100、101 的过滤来源于旧方案实际故障，不是 Windows 的通用垃圾标识。新软件不通过 blanket 规则禁用所有音频或麦克风隐私状态来证明没有旧图标；需要分别核对 Windows 11 原生控件、真实源通知与被旧恢复逻辑重新创建的项目。

### 6.5 微信闪烁与原菜单

外观修改保留原 HWND、UID/GUID、callback、通知版本及源图标所有权。原生托盘图标仍由 Windows 和微信处理鼠标/键盘回调；源发出的 SETVERSION 原样保持，不能强制把旧版应用改为 v4。助手面板执行图标动作时使用已记录的原版本格式及坐标语义，不猜测 callback。

通用层没有可靠的“来新消息”布尔字段。默认仅定制已确认的静态基准外观：源透明/off 帧保留空白，未知告警、徽标、连接或其他动画帧保留原始显示与节奏。静态基准尚不可靠时保持源动态行为，并在确定后应用定制。不得用固定 HICON、周期 NIM_MODIFY 或自行推测的闪烁定时器抹掉源动态状态。

图像判断按实际渲染结果和 AND/XOR mask/alpha 处理；不能把 alpha 全零直接认定为透明，不能仅比较 HICON 数值，不能把每个动态变化都称为未读消息。微信版本适配只有在受控测试及实际自定义前后验证通过后才标为正常。

## 7. 界面与操作方式

采用 WinUI 3 / Fluent 桌面界面，默认约 1120×760，支持缩放和高 DPI。浅色使用温和中性底色及少量蓝色重点，深色保持相同布局；系统材质不适用时仍有完整实色界面。

左侧导航：托盘图标、最小化应用、规则与布局、设置与诊断。主区域是清晰的图标行列表，显示程序、图标、真实状态和少量快捷动作；搜索、筛选和批量操作在列表上方。选中项目后右侧显示原图/替代图、可见性、提示、快捷键和规则匹配信息。路径、句柄和原始错误码收在诊断详情，不挤占日常操作界面。

切换显示/隐藏即时应用；替代图标先预览再应用；拖动排序有明确落点，失败时回退视觉顺序并说明原因；可撤销最近规则修改。实际失败、等待目标出现、规则冲突和权限不足都有独立状态。不能把“规则保存成功”显示成“托盘实际应用成功”。

自己的图标在设置中单独配置，图标关闭前展示可用的重新打开方式。再次启动前台程序连接已有后台并打开界面，保持单实例。快捷键冲突即时告知，不占用已经注册失败的组合键。

快捷面板支持鼠标、键盘、Esc 关闭和焦点恢复。提供完整键盘导航、焦点可见性、屏幕阅读器名称、高对比度和减弱动画；内容列表虚拟化，使用增量通知保持选择和滚动位置。

## 8. 配置、迁移与发行

配置默认保存到当前用户的应用数据目录，包含 schema 版本、规则 UUID、排序、自身图标和窗口最小化设置。用户图像复制到同目录的资产子目录，不依赖某个以后会被删除的临时 PNG。保存采用临时文件、原子替换和最近有效备份；配置损坏时显示明确恢复状态，不默默清空。

项目运行、日志、截图、性能证据、临时实验和发布产物都放在新项目目录的对应子目录；通用编译器优先复用 Common 的 LLVM-MinGW/WindowsSDK。当前 PATH 中只有 .NET 7 SDK，WinUI 3 构建所需工具在实现阶段先核实可复用版本，再准备合适工具链；不覆盖其他项目版本。

可编译工程使用新名称、图标、命名空间及配置目录。旧厂商二进制、逆向 dump、账号凭据、机器配置和用户图标不进入 GitHub 产品仓库。引用外部代码时记录来源与许可，第三方组件版本锁定。

拟用本地目录 `托盘图标助手` 和私有仓库 `CRYS74L/Tray-Icon-Assistant`。Git 身份按 project-git-workflow 核验；新项目从 v0.1.0 开始，每个有意义的项目提交创建 annotated tag 并推送。仍有未完成必备功能时使用 WIP 提交说明，无后缀版本号不等于宣称稳定。

发行提供固定目录可运行的完整包；构建和打包可复现，资源与后台组件版本一致。需要的运行时随包处理，不能要求用户手工执行调试命令。验证没有代码签名时如实记录，不假装已经签名。

## 9. 验收与性能目标

下列数字是设计目标，当前没有测量结果，不是已达到的性能承诺。

| 场景 | 必须通过的结果 |
| --- | --- |
| 已存在图标的首次启动 | 旧软件退出的隔离环境中，取得现有图标并执行规则；不重启 Explorer，不要求逐个重启目标应用 |
| 登录自启时序 | 分别覆盖 Explorer 先启动、助手先启动、目标程序早于/晚于助手启动；登录后规则直接生效 |
| 新增/删除压力 | 受控 x86/x64 目标反复新增、删除图标至少 100 轮；已有自定义项和选择状态无丢失、无重复项 |
| 自定义持续性 | 目标软件反复 NIM_MODIFY、切换动画、修改 tooltip、删除后重建；替代图标/提示一直按规则生效；撤销后恢复最新原状态 |
| 身份稳定 | GUID、非 GUID、多图标、多实例、PID/HWND 复用、动态窗口类、程序升级路径分别验证，不能误隐藏无关图标 |
| 完整识别 | 原生应用目录与 Windows 11 内置控件各自核对；有源注册证据却未入目录必须报告及修复。覆盖 Win32、WinUI、Qt、Electron、WPF、多进程及不同位数，不限应用名单 |
| 旧图标不出现 | 在没有原版和旧补丁参与的环境记录 Windows 11 原生基线；首次启动、自启、手动复核、自然重建、退出恢复都不能新增原本不存在的 Win10 音频/网络/电源/隐私等图标 |
| 微信原行为 | 自定义前后实际消息闪烁、透明/off 帧、读取消息后回稳、鼠标右键菜单和菜单实际动作均通过。受控测试源先覆盖旧格式/v4，但不能代替微信 4.1.15.53 的实际验证 |
| 隐藏与菜单 | 原生托盘及溢出区的可见结果正确；助手中的原菜单和左右键/双击动作有效；协议版本及键盘回调正确 |
| 原生排序 | 拖动、反序、自动排序和新增图标落点在 Windows 实际托盘验证；不是只改助手列表的顺序 |
| 自身图标 | 显示、隐藏、自定义、资源路径失效的恢复、Shell 自然重建均通过；关闭自身图标后仍能重新打开和退出 |
| 退出/注销/关机 | 会话查询响应目标 <50 ms；完整退出目标 <1 s；无退出确认、无新的进程创建、无持续重拉起；取消关机后恢复正常功能 |
| Explorer 自然重建 | 隔离 Windows 环境验证自然重建后的重连；规则、自身图标、窗口恢复和菜单保持正常 |
| 异常隔离 | UI 崩溃、后台退出、管道断开、未知载荷、组件版本不符均不会让 Explorer 无限等待；不能调用无效窗口过程或遗留失效钩子 |
| 最小化窗口 | 指定/最后一个/全部恢复有效；正常退出恢复窗口；故障后的恢复记录按进程实例校验，不能操作复用句柄 |
| 资源与性能 | 关闭 UI 静止 10 分钟测 CPU、私有内存、GDI/USER 句柄及唤醒次数；后台 CPU 初始目标 ≤0.2%，私有内存初始预算 50 MiB，200 个图标场景另测；1000 次更新后资源不能单调泄漏 |
| 事件路径 | Shell 回调不等待外部进程/磁盘，实测 p95 回调目标 ≤2 ms；用户操作到视觉确认目标 ≤200 ms；较慢目标程序不能拖住整个托盘 |
| 界面质量 | 100%/125%/150%/200% DPI，浅色/深色/高对比度，窄窗口及键盘操作；原图、替代图和状态文字可辨认，设置不截断 |
| 全功能核对 | 每行功能清单都有实现入口、运行证据和还原路径；缺项或不生效保持未完成，不用构建测试替代功能验证 |

宿主机的关机、重启、Explorer 关闭/重启受用户全局边界保护，不自动执行。相关破坏性场景在可用的隔离 Windows 环境内验证；真实登录或宿主机关机只能由用户自行操作。合成窗口消息测试证明处理逻辑，不能冒充真实关机端到端验证。

实现顺序：先通过本机托盘能力首关和会话退出路径，再完成规则/原始状态模型，然后完成产品界面及全部功能，最后进行整包回归、性能对照、迁移验证和 GitHub 交付。详细实施计划在总体设计审阅后编写。
