# dev.194 局域网访问权限自动配置

## 问题与范围
现场的网页服务正确监听 `192.0.2.44:18731`，本机直连返回 HTTP 200；Windows 防火墙开启、默认阻止入站，入站拦截提示关闭，原程序没有管理自身的放行规则。此证据说明旧实现缺少必要的网络权限准备，不能仅凭本机 HTTP 200 证明手机可达。

修复在产品代码中完成，不使用固定用户 IP、固定安装路径或一次性手工规则。端口跟随服务实际选择，规则名按可执行路径生成；程序移动位置或端口变化会重新检查。

## 实现
- `LanFirewallAccess` 使用 Windows 防火墙 COM API 查询现有规则与当前策略。
- 规则仅针对当前可执行文件、一个 TCP 网页端口、LocalSubnet 来源，禁止边缘穿越；覆盖 Windows 各网络类别，不要求用户把家用网络手工切换为专用。
- 缺少规则时通过当前可执行文件的专用参数请求系统提权。管理员帮助进程在单实例、监控、窗口和托盘初始化之前执行并退出，不把整个日常程序长期作为管理员运行。
- 已有正确规则时复用，不重复提权。有效策略不允许本地规则时给出失败说明，不尝试修改组织策略。
- 取消系统授权或配置失败时停止网页监听、关闭开关并保存，避免误报可用。
- 保留防火墙全局状态、其他软件规则和 Clash 配置。
- 修复 Windows 将“规则不存在”映射为 `FileNotFoundException (0x80070002)` 的兼容问题，只将该 HRESULT 视为缺失，不吞掉其他策略或 COM 错误。
- 修复现有 CheckBox 模板不显示 Content 导致的开关标签空白，使用与现有设置相同的独立文本标签。

## 验证
- Release 构建与局域网、设置、Windows 通知定向回归通过。
- 实际 Windows 缺失规则查询先重现失败，再修复通过；规则参数限制、稳定路径标识、策略覆盖、端口避让、权限失败回退均有回归。
- WPF 测试注入权限服务替身，不修改测试机器真实规则；产品实机随后通过自身流程创建规则，核实其程序路径、TCP 18731、LocalSubnet、Allow、Enabled 和各网络类别。
- 配置后本机直连 HTTP 200。手机是否正常访问须以手机实测为准；组织限制、第三方防火墙、路由器访客隔离不属于普通程序能绕过的条件。
