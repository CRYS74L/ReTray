# v0.1.26 通用托盘身份与原始图像修复

v0.1.25 对 MacTray 使用了专门的程序名策略。这只能覆盖一个已观察到的程序，本版本删除该特例及按程序名合并旧规则的加载迁移。GUID 图标继续使用 GUID；非 GUID 图标保留原始 UID 和完整路径，在运行时使用原始窗口类、回调消息、提示、图像和同进程注册数量识别图标角色。用户明确指定的窗口、提示和进程筛选条件继续生效。

原 UID 精确匹配优先。UID 改变时，只有同一程序、符合角色证据且候选唯一的注册才能继承偏好。绑定属于原生注册，不全局改写保存 UID；不同进程可以使用不同 UID，共用一个逻辑偏好。同一进程的已确认角色不能再被一个使用旧图像的次图标占用。窗口相同但 UID 不同的图标仍有独立列表身份。源程序的隐藏图像槽参与原 UID 占用判断，不作为公开角色候选。

没有角色信息的旧配置，仅在一条合格旧规则和一个公开角色时允许可撤回的暂时关联。暂时关联不学习提示、图像或新的 UID；迟到的原 UID 会撤回该关联并恢复次图标的原生状态。用户主动编辑当前行后，为它建立当前 UID 的明确规则，保留原规则及列表位置别名，避免迟到图标夺走这次编辑。仅观察身份信息不会重新应用图像、提示或显隐；显式单条和批量重应用仍会清理对应图标的失败缓存。所有身份和规则保存仍走候选验证与事务回滚。

Antigravity 的现场没有发生 UID 或路径变化：同一 PID 44336、UID 3 和旧显示规则仍匹配。更新后它提供 512×512、BGRA8、预乘透明的 Windows.Graphics.Imaging.SoftwareBitmap；旧解码器限制在 256×256，并丢弃 E_INVALIDARG（0x80070057）诊断，因此列表出现空白。这与规则失配是两个问题。

原始 SoftwareBitmap 现在先检查尺寸和像素总量，再转换、读取；支持每边最多 4096 像素、总量最多 4M 像素。源尺寸和全部原始像素指纹保留，用于图像基准和动态判断；展示存储最多 64×64，不复制完整源图的像素向量。原图基准的配置校验使用同一限制，合法的 4096×1024 图像不再因旧 2048 边界保存失败。未知、读取失败和首次尚未就绪的图像会重试；合法透明或空帧继续参与原生闪烁。运行时类型名称仅为可选诊断，不成为解码必要条件。读取状态、HRESULT、原始尺寸、格式和透明模式通过桥接 schema 6 提供。没有使用可执行文件图标替代原始托盘图像。

NVIDIA 类访问受限宿主使用通用只读系统身份回退，不按应用名称提升权限或放宽配置校验。额外修复身份输出残留：不可用或退出进程返回空身份；系统查询用创建时间前后校验路径，避免 PID 重用时混合不同进程的信息。受控进程主动拒绝 PROCESS_QUERY_LIMITED_INFORMATION 的回归确认回退得到正确路径和创建时间，并在退出后清除身份。

验证通过核心 40 项、图标与目录 42 项、系统策略 16 项、SoftwareBitmap 10 项、桥接注册 4 项、进程身份 3 项和 WPF 绑定 4 项；配置往返、尺寸上限、旧规则保留、独立登录任务启用/禁用/更新及同名外部任务保护也通过。另用实际受控托盘程序完成 NIM_DELETE/ADD 将 UID 11 改为 99、多进程不同 UID 同时继承、真实透明 NIF_ICON 帧和原生点击回调检查。受控程序及临时规则在验证后清理。

最终版本在未重启 Antigravity 的同一现场进程读到原生 512×512 图像、64×64 展示图像，live=true、sourceReadState=Ready、HRESULT=0，列表截图可见原图。实际 Antigravity 和 NVIDIA 开关均完成隐藏/显示，原有策略在验证后恢复；保存偏好、资源、提示、列表排序和系统设置进行语义核对，只有身份信息和等价默认字段补充。

即时登录任务沿用 v0.1.25 的当前用户独立任务与固定包激活器。最终包验证关闭后的无参数自动入口退出、关闭时仍可手动打开、启用任务后台启动且不打开界面，并读取相同规则、保持 MacTray 隐藏。电脑和 Explorer 未重启，真实自然登录时机仍待下次登录观察。

本机前后快照中，95 项 Run/RunOnce/StartupApproved 记录和一个启动文件完整一致，226 个计划任务全部保留。225 个任务定义一致；Windows OneSettings/RefreshCache 的 StartBoundary 与 Interval 出现刷新，其他字段相同，变化范围与先前观察到的系统刷新一致。保留 v0.1.25 对该任务 Microsoft 系统处理器与写入权限的证据边界，未取得事件级写入者归因，未修改或恢复该系统任务。QQ、MacType 和其他软件自启动项目未变化。个人配置、目录、截图及诊断证据位于被 Git 忽略的 artifacts。

当多个角色的路径、窗口、提示和图像完全相同，且没有可用的原始 UID 证据时，软件报告歧义并恢复未确认的原生策略，避免把隐藏规则套给另一个图标。缺少历史证据无法可靠反推角色，本版本不会按程序名、最新 UID 或任意候选猜测并永久覆盖旧偏好。

复测入口：build.ps1 的 CoreTests、SettingsTests、AgentVisibilityTests、AgentSystemTests、BitmapTests、BridgeRegistrationTests、ProcessIdentityTests、StartupTests，以及 tests/TrayAssistant.UiTests。native/test-source 支持 WM_APP+31 的受控 UID 重建；实际完整链路脚本和证据留在 artifacts，不作为产品运行依赖。
