# dev.259：新设备上线的 Windows 通知

设置的“通知”卡片新增“当新设备上线时，推送 Windows 通知”，位于“定时免打扰”（含时段）与 IPv6 连接类型提醒之间。默认关闭；开关立即生效，80 ms 后保存最新值，不依赖免打扰时间输入是否有效。重启后保持设置。

新设备按现有 MAC 主键、忽略大小写判断：档案与保留的会话记录中都没有该 MAC，且本次首次记录时明确在线。软移除的档案、历史会话中的设备、先以离线状态记录过的设备均已知；重新上线或重新显示不会发新设备提醒。开关关闭期间发现的设备也正常入库，之后开启不补发旧设备提醒。空记录且已启用时，首次发现的在线设备符合这一规则。

通知标题为“新设备上线：设备名称”，名称与设备列表一致，不显示 MAC。dev.260 按追加要求将正文改为仅发生时间，标题与正文分别限制一行，内容最多两行，长名称单行截断。沿用已有稳定 AUMID 与 Windows App SDK 单通道。遵守定时免打扰；投递前再次检查开关。合并待投递事件时区分新发现和普通上下线，以免相互覆盖。

验证：

- 先加回归，旧代码因首次在线没有通知事件而失败；名称与真实开关两个边界也分别红灯，再修复并通过。
- 档案、软移除、仅有历史会话、首次离线、MAC 大小写、重复刷新、关闭后开启及进程重启的判定通过。
- 启用/禁用持久化、旧 JSON 默认值、加载期间切换和取消旧保存后保留最新关闭状态通过。
- 独立临时数据、离屏窗口和 Fake 通知平台验证一次提交、免打扰、真实开关即时生效、无效免打扰输入不阻止保存、混合事件及浅深色 1180/430 DIP 设置布局。没有改动实际登录、监控记录或开机启动设置。
- 既有通知单通道、3 秒离线确认、设置不重连及持续输入响应式回归通过；Release 构建 0 警告、0 错误。
- 真实 Windows 横幅已确认：用独立临时档案沿新设备判定→窗口投递→既有 Windows App SDK 链触发功能验证。dev.260 名称与上线提示共用首行、时间在第二行，长名称单行截断，不显示 MAC，截图为 `runtime-data/new-device-dev259/real-toast-04.png`。测试记录未写入真实设备历史；部署重启后由正式安装路径重新注册通知身份。

Fake 平台用于确定性检查，真实横幅由独立验证另外确认。诊断日志和设置截图保存在忽略目录 `runtime-data/new-device-dev259`，本轮未运行旧全量自检，不声称其全部通过。
