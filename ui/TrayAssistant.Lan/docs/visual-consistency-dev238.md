# dev.238 视觉一致性与窗口客户区修复

## 本轮修改

- 摄像头与插座精确恢复 dev.234 的图形：摄像头为 webcam；插座为该版本的圆角外框和插孔。桌面与网页仍从同一份 SVG 生成。已逐行比较两项生成几何，和 dev.234 完全相同。
- 设备详情、路由器页内容与设置页一样限制为 720 DIP，居中自适应。标题设备图标左对齐，去除原 74 DIP 列中居中带来的 5 DIP 额外缩进。
- 下拉当前选中项的文字与勾使用主题蓝；补强菜单项重新装载、尺寸变化时的胶囊圆角，避免半径停留在首次测量的零值。
- 收起侧栏的路由器和设置图标统一使用 MutedTextBrush，与展开侧栏按钮一致。
- 深色中性背景按用户明确的“过亮、发灰”反馈降低灰度与透明叠加量，涵盖外层面板、内层卡片、普通设备胶囊、确认层和历史时长。保留 Acrylic API、原始底层染色参数及浅色材质。相同测试环境的窗口合成截图中，卡片背景采样从 RGB 58 降至 45，侧栏背景从 48 降至 40。这是本轮视觉调整，不声称旧版与新版所有像素相同。
- 在线/离线的两套滚动条固定在原位，与列表共用 480ms CubicEaseOut 淡出/淡入。目标没有滚动条时渐隐，存在时渐入，完成后恢复正常滚动交互。
- 右侧三个内容页增加固定视口渐隐，上下沿随滚动偏移渐进展开，最大 36 DIP。使用独立模板，不改变下拉弹层的滚动模板。
- Mesh 连线采用与 CardCornerRadius 同源的 24 DIP 圆弧，为圆弧留出缩进空间；图标/圆底比例改为 18/36。名称、主路由/节点和回程标识放在同一流式行，极窄空间自然换行以免裁切。

## 最大化原因与处理

原先 WindowChrome 将本应不可见的最大化缩放边框也纳入客户区。主屏工作区为 2560×1380 时，原客户区从 (-9,-9) 延伸至 (2569,1389)。旧回归只核对裁剪区域，掩盖了内容越界。

现在通过 WM_NCCALCSIZE 为最大化客户区使用当前显示器工作区。保留 Windows 的原生窗口状态和不可见缩放边框，不切换 HWND 风格，不添加自定义窗口区域，不变更 Acrylic 路径。增强回归直接检查 WindowRoot 的屏幕坐标。主屏客户区为 (0,0)–(2560,1380)，竖屏副屏为 (2560,0)–(3370,1440)。原生外框矩形仍可能含 Windows 的不可见缩放边框，不能把该矩形与实际内容范围混为一谈。

参考：[微软 WM_NCCALCSIZE 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-nccalcsize)。

## 验证范围

- Release 构建零警告、零错误。
- 控件完整回归、下拉对齐与重复开关/主题切换胶囊回归、侧栏/拓扑回归、快速反向筛选回归、响应式导航回归、原生窗口及关闭到托盘回归。

- Mesh 三层关系在 1180、430、380 DIP、浅深两种主题下生成并检查截图；节点关系来自真实 ParentNodeId。
- 使用独立测试进程和离屏渲染。材质探针使用底层无激活测试窗口及 Windows.Graphics.Capture，比较最小化前后；不修改用户设置。真实鼠标最大化后拖拽未由本轮自动化执行，原生状态/命中/还原和材质重应用已测试。
- 网页图标画布边界与内嵌字体在桌面及手机尺寸使用无头浏览器检查。

安装、文件哈希及 Git 状态以本轮交付报告为准；测试图像、测试程序、安装备份都位于忽略目录 .tools，不进入仓库。
