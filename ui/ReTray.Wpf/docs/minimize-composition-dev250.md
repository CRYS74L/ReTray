# dev.250 最小化材质同步

用户录屏（14.85 秒、2560×1440、60 FPS）中，同一次连续操作既有保留材质的最小化，也有缩向任务栏时突然透出清晰壁纸的最小化；恢复正常大小后 Acrylic 返回。逐帧对照确认背景模糊丢失，界面文字和控件仍在。

## 原因与修改

旧代码把 `CompositionTarget.Rendering` 加上 Background 回调当成已完成渲染的通知。实际上 Rendering 在发送场景之前触发；WPF 渲染线程的批次可能仍待提交，`DwmFlush` 也不能代替 WPF 自己的批次同步。旧代码最后才修改底层背景，然后立刻最小化，留下提交竞态。

改为可取消的 Dispatcher 请求：结束正在进行的列表/详情动画，同步提交当前正常画面，再截图；提前准备完整快照和底层背景，同步提交这帧，再启动原生最小化。同步入口隔离在 `WpfRenderSynchronization`，使用本项目自包含 .NET 8 WPF 的 `MediaContext.Resize(null)` 和 `CompleteRender`，然后调用 `DwmFlush`。内部入口来自 [WPF 官方源码](https://github.com/dotnet/wpf/blob/v8.0.0/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/Media/MediaContext.cs)；更新运行时时必须重新验证这些入口。整个窗口完全位于屏幕外时不等待可见帧；部分可见或被其他窗口遮挡的屏幕内窗口保留同步。

没有修改常态 Acrylic 颜色、透明度、模糊策略、窗口框架、主题资源或渲染器，没有增加常驻截图背景。恢复时沿用原有快照清理；关闭到托盘和退出时撤销待执行的最小化请求。同步渲染和布局回调返回后重新检查取消状态。

## 验证方式

`--minimize-composition-regression` 在独立测试进程中显示测试窗口和棋盘背景，录制 60 FPS 动画，随后解码像素。角落颜色标记标识每次最小化/恢复的区间，空详情图标的位置与大小用于识别移动中的窗口；每个区间必须有实际移动帧才可通过。高对比度棋盘穿透材质时测试失败。每轮还比较正常窗口三个材质区域的 RGB 均值，并检查快照已撤销。测试也覆盖排队最小化后关闭到托盘、托盘隐藏期间拒绝最小化、恢复及退出取消。

本机像素 fixture 要求主屏幕至少 2000×1200、125% 缩放，以及 PATH 中可用的 FFmpeg；不符合时明确报错。录制和测试窗口在结束时释放，超时由独立测试进程清理本次 FFmpeg 子进程并退出。测试不会初始化真实设备监测、读取路由器密码或修改用户设置。输出位于 `%TEMP%\LanDeviceMonitor-minimize-composition`。

旧录制的重放检验可以使用 `--analyze-minimize-recording <棋盘测试录像>`；这是重放分析，不代替有逐次动画覆盖门槛的实测回归。故障为概率性：旧版也可能在有限轮次中全部保留材质。

旧列表切换专项 fixture 修正了 `CenterScreen` 覆盖离屏坐标的问题，并删除恢复后的无界 `ContextIdle` 等待；快照清理本身由 StateChanged 同步执行。

## 本机验收结果

- Release 构建：0 警告、0 错误。
- 实际动画像素回归：16 次浅/深色最小化与恢复，32 个动画区间均有移动帧覆盖，最终累计 235 个有效移动材质帧、0 个清晰棋盘泄漏帧。
- 正常材质三个区域的 RGB 均值最大差：浅色 1/255、深色 0/255。截图残留检查及排队最小化取消检查通过。
- 列表切换期间最小化专项、关闭到托盘专项通过。
- 重放原故障棋盘录像可检测到 14 个泄漏帧；此重放不作为逐周期覆盖的替代。
- 旧全量自检报 33 项失败；以 dev.249 部署 DLL 重跑得到同样 33 项，逐项文本对照无差异。两版全量自检均未正常结束其前台线程，已清理本次测试进程，未将它称为全量通过。失败项如下，保留原始名称：

- 总量卡片悬停日期区间应仅显示月日范围
- 设置界面应显示当前实际软件版本
- 上下线历史界面应分别显示日期与时间，隐藏年份和秒，后台仍记录完整日期时间
- 主窗口启动与托盘菜单打开不应触发异常：
- 主窗口左右板块内容溢出时都应显示具有实际高度的细滚动条：左侧可见=False，左侧滑块=0，右侧可见=False，右侧滑块=0
- 左侧设备条块的悬停与非悬停状态应使用非线性动画
- 托盘菜单的两个选项应分别使用独立的非线性悬停动画
- 托盘菜单选项悬停层应加深至 18.8% 不透明度，图标与文字间距应增加 8 DIP
- 托盘菜单“打开主界面”的图标与文字应在同一垂直中心线上
- 浅深色材质、下拉栏、时间轴与滚动条颜色资源应使用指定的不透明度和主题值
- 深色模式下路由器与设置按钮的提示框应使用可读的深色背景与文字
- 设备详情页中设备设置区域应位于上下线历史区域之后
- 输入框、密码框、选择框、下拉框与卡片的大小比例应与 v0.1.0-dev.48 一致
- 免打扰开始与结束时间输入框应同为 86 x 40 DIP，且时间文字水平、垂直居中
- 设备自定义名称输入框应保持完整单行显示，并与设备类型选择框同为 48 DIP 高度
- 设备详情标题文字应在原位置基础上向右移动 8 DIP
- 深色模式右侧详情设备图标应与左侧设备列表共用适配主题的背景资源
- Windows 应实际接受不会随失焦自动切换为回退色的持久 Acrylic 材质写入：
- 最小化、还原和最大化期间应保持同一个持久 Acrylic 背景，且不创建覆盖 WPF 内容的独立合成目标（）
- 最小化前应应用可进入 DWM 动画快照的非聚焦过渡材质，还原后必须立即清除且不影响常规态
- 主窗口最小化命令应在下一渲染帧进入动画，还原后也应在下一渲染帧恢复常态材质，不得额外停留固定延时
- 用户选择新设备后，实时数据刷新不应把左侧选择抢回旧设备
- 实时刷新应复用已有设备视图模型，避免每秒重建 WPF 列表项
- 在线与离线统计卡应分别筛选设备，并按最近上线或离线时间倒序排列
- 在线与离线统计卡悬停时应轻微放大上浮，并按非线性动画过渡
- 在线与离线切换时设备列表应按按钮左右方向水平滑动（）
- 在线与离线切换导致设备详情变化时，右侧详情面板应使用原有切换动画（）
- 在线与离线切换时，左侧列表和右侧详情应沿用原有同步动画时序
- 在线与离线切换动画期间应使用渲染缓存降低重绘开销，不改变动画时序
- 列表切换启用渲染缓存前应先完成进入列表的首个视觉条目生成，避免首帧把旧列表显示成目标列表
- 详情上下线历史应复用稳定的数据源，切换设备时不重建整个历史控件树
- 设备管理栏应位于上下线历史下方、只对离线设备显示，并复用重启路由器按钮样式
- 确认框应使用更亮的圆角矩形样式、非线性弹出动画，并支持点击外部自动收回

## 现有边界

截图仍使用原有屏幕像素捕获，因此其他窗口覆盖软件时可能被截入快照；本次没有宣称解决该原有遮挡捕获限制。有限次动画测试不构成所有硬件与驱动下永不复发的保证。正常材质的视觉基线以本机当前版本为准。
