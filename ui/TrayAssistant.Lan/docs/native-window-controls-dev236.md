# dev.236：恢复红绿灯之前的窗口实现

## 恢复基线与范围

采用红绿灯加入前的 `v0.1.0-dev.208`（`42f6ea2`）作为窗口恢复基线，只恢复窗口相关实现。

- 恢复该版本的 40 DIP Windows 样式顶栏、最小化/最大化/关闭按钮、系统命令及原有最小化材质保护流程。
- `MicaWindowService.cs` 与 dev.208 完全一致；原有浅色/深色 Acrylic 参数恢复，撤销本轮试验的 Desktop Acrylic 路径。
- 删除红绿灯控件、红绿灯感应区及 dev.235 增加的窗口裁剪补丁。
- 保留关闭到托盘、持续监测和同一 HWND 恢复行为，用户已明确确认。
- 最大化还原及拖动结束后重新应用原材质，避免框架状态改变后丢失透明表面。
- 保留最新设备栏、内嵌字体、图标、窄屏导航、路由器页面和其他业务修复。

历史 dev.208 的按钮采用 Windows 样式绘制，并调用 Windows 系统命令；这里准确恢复该历史实现，不将它描述为操作系统直接绘制的非客户区标题栏。

## 验证

- Release 构建成功，0 警告、0 错误。
- 历史比对：`git diff 42f6ea2 -- src/LanDeviceMonitor.App/Services/MicaWindowService.cs` 无差异。
- 恢复窗口回归：40 DIP 顶栏、Windows 控制符号、系统标题栏命中、无红绿灯、双屏最大化/还原、原材质、最小化/还原、关闭到托盘通过。
- 控件回归：浅/深色、980/1180 宽度、侧栏收放、输入框和下拉菜单通过。退役的红绿灯专属断言已移除，其余行为继续检查。
- 关闭到托盘回归通过：取消真正关闭、保留普通窗口表面、原生隐藏并恢复完整 UI。
- 实际安装版发送系统最大化、还原和拖动结束消息后，以 Windows Graphics Capture 仅捕获该窗口；`restored208-after-cycle.png` 显示原有磨砂材质仍在，未出现系统按钮与红绿灯叠加。没有把消息序列检查描述为实际鼠标拖拽。

本轮最初的标准非客户区标题栏和 Desktop Acrylic 尝试被用户指出不符合原视觉，均已撤回；它们的截图不作为最终成果依据。
