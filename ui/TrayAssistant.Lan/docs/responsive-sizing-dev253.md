# dev.253：连续调整尺寸时及时切换布局

用户确认 dev.252 已消除尺寸变化卡顿；新的 10.3675 秒、60 FPS 录屏暴露了布局切换滞后。本次按录屏核对完整过程，并抽出缩小 1.8–3.4 秒、放大 5.7–7.3 秒两段的每帧图像。约 2.78 秒时仍保留双栏，右侧详情被挤成狭条；约 6.77 秒时窗口已经变宽，仍是单栏列表，内容停在旧宽度并留下大片空白，对应用户截图。

## 原因与修改

跨过 900 DIP 阈值时，`WorkspaceGrid_SizeChanged` 把模式切换合并到 `DispatcherPriority.Background`。持续调整窗口尺寸时输入尚待处理，后台回调不能及时运行；而该路径提前返回，当前模式的内容宽度也停止更新。于是缩小时双栏保留过久，放大时单栏保留过久，松开后才恢复。

回调现在使用 `DispatcherPriority.Render`，在当前布局返回后、待处理输入之前执行。仍只保留一个回调并读取执行时的最新宽度，避免在 `SizeChanged` 内同步重入。没有改变现有 900 DIP 阈值、双栏比例、单栏导航、字体、常态材质及上一版 DPI 像素对齐/渐隐画刷缓存。

## 验证与范围

- 新增 `--responsive-sizing-regression`：每次 Dispatcher 运行只处理到 Input，并以哨兵确保 Background 没有运行，模拟持续尺寸输入下的调度条件。旧代码明确失败：窗口 898 DIP（工作区 898.4）仍同时显示列表和详情。修正后浅色/深色、380–1340 DIP 双向跨阈值、单栏内容填满、双栏及时恢复及合并回调采用最新宽度通过。
- 新回归使用独立离屏窗口，取消应用真实启动，不读取/修改实际监控数据或登录配置。
- `--responsive-navigation-regression` 通过：列表、详情、返回、设置、路由器、收起侧栏及放大恢复行为保持正常。
- `--resize-cache-regression` 通过：侧栏实际宽度不超过对齐上限，等价渐隐遮罩复用及滚动/高度改变更新保持正常。
- 同一丰富数据 fixture 的 720 次连续细步重排：最大 60.79 ms、P95 28.66 ms、累计 11369.31 ms；上一版对应 55.99 ms、28.73 ms、11506.92 ms。未再出现此前上秒级的布局循环。这里是同步重排诊断，并非真实匀速鼠标拖动或 60 FPS 保证。
- 最小化材质回归通过：16 轮、228 个有效移动材质帧、0 锐利背景漏底；常态浅色平均像素差最多 1/255，深色 0/255，取消路径通过。
- 最终 Release 构建 0 警告、0 错误；代码评审未发现产品阻断项。本轮只运行受影响回归，不宣称旧全量自检全部通过。
