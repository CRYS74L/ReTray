# dev.251 窗口缩放、自适应切换与深色细节

## 本次要求

- 修复连续调整尺寸时，四列/两列及双栏/单栏切换造成的窗口停顿。
- 流量统计标题下空隙与连接信息/历史标题一致。
- 降低深色滚动条及设备设置分隔线的亮度。
- 深色 Mesh 主路由与子节点使用一致的卡片底色，保留浅色层级。
- 保持既有常态 Acrylic 和 dev.250 最小化材质修复。

## 缩放路径

用户 8.318 秒、60 FPS 录屏中，窗口边缘在内容重排附近停顿。尺寸回调每次都重置导航动画及整套自适应结构；Justify 的自适应列和标题又把已适合的文本块按不同约束重复测量。

窗口现在仅在真实跨越断点时切换结构，待处理回调合并最新宽度；高度变化不取消导航动画。适合的 intrinsic 文本测量直接复用，仍保留不适合/换行情况下的有限宽度测量。

原生 live sizing 中，WPF 默认还会在每个尺寸消息后等待渲染线程完成呈现。主窗口是自绘客户区框架，处理 `WM_ENTERSIZEMOVE` 通知以采用异步呈现，继续传递 `WM_SIZE` 和 `WM_EXITSIZEMOVE`，保留尺寸更新、键盘重同步及结束后的完整背景刷新。依据 [WPF HwndTarget 源码](https://github.com/dotnet/wpf/blob/v8.0.0/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/InterOp/HwndTarget.cs) 和 [进入移动/缩放循环通知](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-entersizemove)。拖拽期间客户区呈现可能短暂落后窗口边缘；不把延迟上限或 60 FPS 当成保证。正常状态 Acrylic 参数未变，最小化仍使用单独的同步快照提交。

## 标注修正

流量标题所在行受 36 DIP 区间按钮的高度影响，标题居中额外增加了下方空隙；底部 margin 从 11 减为 3 DIP。字形到卡片的实际空隙测得历史 14.2、流量 13.4 DIP，相差一个物理像素以内。

设备设置分隔线改为 DynamicResource，避免继续持有浅色画刷。深色滚动条常态/悬停颜色分别改为 `#40666666` / `#807A7A7A`，浅色保持原值。

Mesh 主路由使用独立的主题画刷：浅色沿用原强层级 `#88FFFFFF`，深色与子节点卡片同为 `#A4242424`；拓扑缩进、连接线、角色文字不变。

## 验证

- Release 构建 0 警告、0 错误。
- 新 `--resize-layout-regression` 覆盖原生进入/退出尺寸循环、连续宽度、高度调整中保留导航动画、未处理回调前快速宽/窄折返、恢复双栏、字形空隙、分隔线主题切换和 Mesh 明暗层级。dev.250 部署 DLL 对照可复现导航被取消，修改版通过。
- 原生窗口截图验证浅/深色详情与 Mesh；原生尺寸消息录像核对切换过程，没有看到布局闪空。
- 一轮相同 fixture 的原生同步段总耗时：旧版 715.5 ms、修改版 540.7 ms；含回调、呈现及每步 20 ms 观察期的总周期约 1489/1428 ms。其他轮次存在波动，录制本身也影响耗时，这些数据不作为帧率证明。
- 现有 `--responsive-navigation-regression` 通过，覆盖 1180/760/430/380 DIP 列表、详情、返回、设置和路由器页面。
- dev.250 实际动画像素回归重跑通过：16 轮、32 个移动动画区间、237 个有效材质帧、0 漏底；排队最小化取消及常态材质对比通过。
- 旧全量自检仍有既有失败及退出线程问题；不将它称为全量通过，沿用并对照 dev.250 的失败清单。

本地原生截图依赖项目已有 `.tools/native-capture`，仅用于 QA；录屏、日志和 fixture 截图位于忽略目录 `runtime-data/resize-audit`，不含在发布提交中。
