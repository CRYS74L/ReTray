# 应用升级身份与 Shell 恢复

0.1.75 为普通桌面程序的 `app-版本号` 安装布局增加跨版本匹配。稳定身份保留绝对安装根目录和完整的程序相对路径，只归一化有效的版本目录；不同安装位置、不同可执行文件和不同图标角色继续独立处理。旧规则无需改写，列表沿用已保存的身份。相同策略的跨版本副本可以合并，冲突策略继续报告歧义。

图标编号变化继续使用现有角色证据与唯一候选判定。稳定 GUID 继续精确匹配；由程序路径生成的 H.NotifyIcon GUID 只有在新旧值均符合已验证的派生算法时才跨版本关联。安装布局参照 [Squirrel.Windows 的 AppDirForVersion 实现](https://github.com/Squirrel/Squirrel.Windows/blob/develop/src/Squirrel/Utility.cs)，原生图标操作继续遵守 [NOTIFYICONDATA 的窗口、编号和 GUID 语义](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)。

Shell 桥接同时验证宿主进程仍存活、窗口归属和当前托盘窗口，宿主退出后释放旧请求状态。系统控件尚未就绪时保留可重试错误码，保存的策略在短暂失败后延迟重试。读取状态和策略应用状态分别保存，成功读取会清除对应故障；界面恢复控件并移除该次读取错误，同时保留后来发生的其他操作错误。

原生运行库和 Shell 桥接均带版本资源，打包前必须与项目版本一致，避免界面升级时带入旧原生组件。

回归覆盖跨版本规则、图标编号变化、路径派生 GUID、同程序多图标、冲突策略、列表位置、宿主退出、系统策略短暂失败和界面读取恢复。测试使用虚构路径、隔离宿主进程与独立管道。
